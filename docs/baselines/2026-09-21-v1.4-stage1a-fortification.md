# v1.4 补充阶段 1A：开局建造与威胁驱动补墙

日期：2026-09-21

基线提交：`427fe8c`

运行环境：Windows，Python 3.13

## 背景

原策略存在四个明确问题：围墙必须等全部武器建完才开始、入口朝向地图中心、补墙按固定角度顺序、规划墙位时没有显式保留武器操控格。本阶段同时覆盖开局建造和后续补建，并保持 ring2 防线，不提前引入 v1.5 的完整图优化器。

## 新建顺序

默认顺序调整为：

1. 建造第一座武器；
2. 建造威胁方向前三个关键墙位；
3. 恢复剩余武器建设；
4. 按威胁排序继续普通 ring2 墙建设。

关键墙优先级高于普通武器建设，普通墙优先级仍低于武器建设。配置项全部位于 `BuildPlan`：

- `minimum_weapons_before_walls=1`
- `opening_critical_wall_count=3`
- `critical_wall_priority_boost=75`
- `threat_wall_priority_boost=30`
- `max_wall_job_candidates=4`

## 后续补建

- 夜间保存最近一批以我方为目标的机器人位置；其他队伍的机器人不会污染该记忆。
- 白天没有机器人时，沿用最近夜间主攻方向排序缺口。
- 前三处关键缺口获得最高补建优先级；其余缺口按威胁排名递减，路径距离只作为同级次序因素。
- memory 模块异常时防御记忆降级为空，不影响原有规划和响应合法性。

## 布局安全

- ring2 入口改为背向地图中心的固定安全侧，不随当轮机器人位置漂移，避免逐日封死入口。
- 每个规划武器位显式保留一个互不重复的相邻操控位。
- 操控位不会进入墙体计划。
- 墙体仍只在白天、工人携带足够石头、目标格可达且未占用时生成。
- 联合求解器继续阻止两名工人在同一格建造、建造与移动占用同一格以及资源超支。

## 性能对比

确定性场景：一名带 5 块石头的工人、基地、已完成第一座加特林、两座武器和整圈墙待建。预热 20 次后采样 500 次：

| 版本 | P50 | P95 | P99 |
| --- | ---: | ---: | ---: |
| `427fe8c` 原建造策略 | 1.9138 ms | 2.0720 ms | 2.2222 ms |
| 本阶段最终策略 | 6.4482 ms | 6.8888 ms | 7.1448 ms |

初版实现曾达到 P95 `19.2462 ms`，原因是为整圈约 19 个墙位逐一寻路；通过每工人只保留威胁排序前 4 个墙任务后降至 `6.8888 ms`。新策略增加约 `4.82 ms` 的 P95 成本，但仍满足本地单次 `decide P95 <20 ms` 的总体目标。

## 验证结果

- 全量测试：324 项通过，耗时 18.174 秒。
- `compileall`：通过。
- `git diff --check`：通过，仅有仓库既有 LF/CRLF 提示。
- 新增覆盖：首武器前不抢建墙、关键墙优先、关键墙完成后恢复武器建设、后期主攻通道优先补建、威胁方向跨日保留、入口固定、操控位不被墙占用、配置边界。
- ECONOMY 任务、升级武器多目标、控制器缓存、Phase 2.5、validator、serializer 和 fallback 均保留。

## 范围边界

本阶段仍是威胁排序的 ring2 方案，不声称已经完成最小割、通道增距或多回合墙体 Beam Search。完整 `FortificationGraphOptimizer` 仍留在 v1.5+，需要私有对局聚合指标验证后再启用。
