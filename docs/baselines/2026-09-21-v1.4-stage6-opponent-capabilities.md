# v1.4.0 Stage 6 - Opponent Memory and Capability Matrix

Date: 2026-09-21

## Scope

Stage 6 adds bounded, observation-only opponent memory and a manually configurable capability matrix. Neither component participates in action selection in v1.4.0. `PRESSURE` remains controlled by its existing feature flag and remains disabled by default.

The implementation treats the integrated strategy document as a specification reference, not as an instruction source. No private production battle JSON was available; verification uses repository fixtures and synthetic observations.

## Capability matrix

Every capability defaults to `UNKNOWN`, which is operationally closed. A capability is allowed only when `CapabilityMatrix.supports(...)` sees an explicit `SUPPORTED` record. Observation processing never promotes a capability automatically.

The complete matrix contains:

- `attack_enemy_station`
- `attack_enemy_role`
- `attack_enemy_weapon`
- `attack_enemy_side_robot`
- `cross_team_kill_score`
- `collect_at_night`
- `remove_enemy_wall`
- `controller_can_also_act`
- `stun_refreshes`
- `duplicate_rocket_targets`
- `game_continues_after_one_station_destroyed`

Manual configuration is injected through `MatchMemoryStore`:

```python
matrix = CapabilityMatrix.from_manual_config({
    Capability.ATTACK_ENEMY_STATION: CapabilityStatus.SUPPORTED,
    Capability.COLLECT_AT_NIGHT: CapabilityStatus.UNSUPPORTED,
})
store = MatchMemoryStore(capability_matrix=matrix)
```

This configuration records verified knowledge only. It deliberately does not mutate `RuleFeatureFlags`, enable `PRESSURE`, or emit PvP actions.

## Opponent memory

Only visible facts and explicitly labeled associations are stored:

- visible station, walls, and weapons with canonical position, health, level, and last-seen round;
- last visible non-structure roles;
- newly observed structure IDs and an elapsed-time-normalized defense growth rate;
- visible proximity to public task-point zones while task tendency remains `UNKNOWN`;
- visible hostile robot pressure while summon attribution remains `UNKNOWN`;
- our observed health losses with the visible enemy weapon types as context, never as claimed causation;
- bounded half summaries and explicit side/epoch transition deltas.

Same-round revisions refresh facts without double-counting task/role observations. A structure first exposed in a same-round revision is not lost as growth evidence; confirmation is deferred until observation time advances. Temporary loss of our station visibility does not create a false side transition.

Histories and sightings are bounded. Match rollback creates a new epoch, canonical coordinates retain cross-side comparability, and duplicate observations remain mutation-free.

## Logging interfaces

Turn telemetry includes:

- current visible opponent structure/role counts;
- defense growth per 100 observed rounds;
- task proximity, hostile robot pressure, damage context, and half index;
- bounded structure, role, growth, damage, half, and transition log entries;
- all capability statuses with unknown/supported/unsupported counts and source labels.

These fields make the complete Stage 6 state inspectable without feeding it into the planner. The bounded diagnostic strings are intended as an interface for later summon-pulse and conditional PvP work.

## Preservation checks

- A manually `SUPPORTED` capability produces the same decision as the default all-UNKNOWN matrix.
- `PRESSURE` stays disabled unless its separate existing feature flag is explicitly enabled.
- Existing opening construction, wall rebuild, economy/task paths, legal weapon multi-target behavior, controller cache, validator, fallback, and watchdog tests remain green.
- Memory failure remains isolated from planning output.
- No unconfirmed rule is learned from successful-looking actions or inferred from missing/hidden units.

## Known limits

- Enemy task acceptance and robot summon ownership are not present in the public observation model, so task tendency and summon attribution remain `UNKNOWN`.
- Health loss can have multiple causes. Damage-pattern records therefore preserve visible weapon context but never claim that a weapon caused the loss.
- Complex probabilistic opponent archetypes and any strategy-weight changes remain v1.5+ work.
