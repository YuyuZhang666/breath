# v1.4.8 Action lifecycle observability

## Scope

This increment closes the evidence gap around the first-night R88 to R92
transition. Aggregate counts could show that one command disappeared, but
could not show whether it was absent at candidate generation, omitted by the
planner, rejected by validation, or missing from the final response.

## Action lifecycle

Every bounded turn record now includes:

- planned actions immediately returned by the strategy engine;
- actions retained by protocol validation;
- actions removed or changed at validation;
- one correlated lifecycle entry for every actor appearing at any stage,
  including the final serialized response action.

Entries contain actor id, observed unit type, action kind, controller id,
target positions, item or structure name, and quantity when applicable. Task
answers and other free-form content are not copied into telemetry. Logs are
deterministically sorted and capped at 32 actors.

## Weapon diagnosis

The lifecycle entries complement the existing Phase 2.5 per-weapon record,
which already includes weapon id, type, health, position, cooldown, assigned
controller, controller position, candidate count, no-candidate reason, and
selected action. The two records can now be joined by actor id to determine:

1. whether a weapon generated candidates;
2. whether joint fire selected an attack;
3. whether a later phase replaced that action;
4. whether validation retained it;
5. whether it appeared in the actual response payload.

This is diagnostic only and does not change combat selection or budgets.
