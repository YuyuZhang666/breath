# v1.4.9 Forecast validity and segmented performance

## Scope

This increment makes a stable survival margin auditable instead of treating it
as proof of either correctness or stale cache use. It also separates timing
records produced while the station is alive from cheap responses after the
station has already been destroyed.

## Forecast input identity

Full, lightweight, incremental, and day-rebased forecasts now carry a
deterministic 16-character input signature. The signature covers the model
version, day and round within the phase, active-task presence, friendly unit
state, and robot state. Incremental updates refresh the signature even when
the calculated survival margin is unchanged.

Each turn records both the current observation signature and the signature
used by the retained forecast. The telemetry explicitly reports whether input
changed, whether the forecast is current, and the margin delta from the prior
forecast. This distinguishes a mathematically stable margin from a forecast
that did not consume the latest observation.

## Input evidence

The forecast record also includes current station health, hostile robot count,
hostile total health, hostile attack power, ready weapon count, and minimum
hostile distance to the station. These fields are recorded before emergency
returns, so emergency-reserve behavior remains diagnosable without running a
heavy forecast.

## Performance segmentation

Every engine turn is classified as one of:

- day_alive;
- night_alive;
- post_station_loss;
- station_unknown.

Replay analysis can therefore report daylight construction latency, live
night combat latency, and post-loss response latency separately. The large
volume of near-empty post-loss turns can no longer silently lower the reported
combat average.
