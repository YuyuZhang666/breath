# v1.4.7 Build failure recovery

## Scope

This increment prevents an unactionable build target from monopolizing the
day planner. The replay symptom was a rocket build being retried at the same
coordinate for many rounds while the wall gate remained blocked.

## Recovery state

Match memory now records bounded build failures by structure name and target.
Each record tracks consecutive failures, the last failure round, and a short
exponential cooldown. Records expire after 20 rounds, are cleared by a
matching successful build, and reset on match rollback or side change.

The first failure pauses that exact target for one planning round. A second
consecutive failure marks the target for deterministic rerouting. At most 32
records are retained.

## Planner behavior

- Weapon builds keep their planned layout target until it fails.
- A first failure applies a brief cooldown instead of issuing the same command
  immediately again.
- Repeated failures or currently occupied targets select a reachable free cell
  beside the station that does not overlap planned weapons, walls, or
  controller positions.
- If no legal alternate exists, the build is skipped for the round rather than
  producing an endless invalid-command loop.
- Wall construction consumes the same persistent cooldown state in addition
  to its existing one-turn feedback check.

## Telemetry

Turn records now expose the active failure count, cooldown count, reroute
count, bounded failure details, and weapon target reroute decisions. This is
enough to distinguish insufficient gold from an invalid or occupied build
coordinate in the next replay.
