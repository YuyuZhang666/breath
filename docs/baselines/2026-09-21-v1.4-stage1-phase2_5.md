## 实现内容

- 新增 `strategy/joint_fire.py`，每座武器最多保留 4 个攻击方案和一个不攻击方案，三武器联合枚举不超过 125 组。
- ThreatAssessment 综合到站距离、下一回合威胁、关键墙/武器/操作者威胁、攻击力和击杀分。
- SURVIVE、DESPERATION 优先削减生存威胁；SCORE 优先确定击杀和击杀分；其他模式采用平衡排序。
- 加特林按合法 90 度锥、命中结果去重和前排遮挡压缩候选。
- 电磁炮按实际 `attackPower` 计算穿透，并按相同伤害序列去重。
- 火箭只从机器人周围 3×3 生成落点，计算中心、溅射、重叠与过量伤害；冷却时不生成攻击。
- 联合评分显式惩罚重复伤害、过量伤害与火箭冷却机会成本。
- 控制器分配加入当前可开火、武器模式价值、移动距离和操作者风险；缓存签名覆盖武器血量、等级、射程、攻击力和冷却。
- Phase 2.5 不可模拟或异常时自动降级到原 Phase 2。
- 未验证的跨阵营机器人攻击默认关闭，Phase 2 降级路径同样遵守该开关。

## 关键接口

```python
plan_joint_fire(
    observation,
    world,
    intent,
    *,
    controller_assignments=None,
) -> JointFirePlan
```

`JointFirePlan` 返回合法决策、枚举组合数、活跃武器数、候选数以及候选生成/联合评分耗时。`plan_turn` 在夜间优先调用 Phase 2.5，并通过注入的 `TelemetryRecorder` 记录：

- `phase2_5_ms`
- `phase2_5_fallback_count`
- `phase2_5_combination_count`
- `phase2_5_active_weapon_count`
