# v1.4 阶段 2：Phase 3 根动作 Rollout

日期：2026-09-21

## 范围

本阶段只完成 Phase 3 根动作化，不提前实现阶段 3 的
`NightRiskForecast` / `TailEstimator`，也不提前实现阶段 4 的
`ComputeGovernor`。

夜间决策链调整为：

```text
Phase 2.5 基线
  -> 事件触发器 NONE / LITE / FULL
  -> 少量有语义的根动作
  -> 后续回合统一使用 Phase 2.5 联合火控
  -> Full 失败降 Lite
  -> Lite 失败复用 Phase 2.5 基线
  -> Phase 2.5 内部失败再降旧 Phase 2
```

## 关键接口变化

- `Phase3Level`: `none`、`lite`、`full`。
- `Phase3Config.budget_for(level)`：
  - Lite：最多 4 根、1 场景、2 回合、80ms；
  - Full：最多 8 根、2 场景、4 回合、250ms。
- `select_phase3_level(...)`：根据基地承伤、资产死亡、波次突增、
  新进入墙压、火箭刚就绪等事件选择档位；持续不变的墙压不重复触发。
- `choose_joint_fire_attacks(...)`：从 Phase 2.5 抽出的状态级联合火控，
  实时策略与 rollout 后续回合共用同一评分实现。
- `search_night(...)` 新增 `level`、`intent` 和 `baseline_decision`，并支持
  deadline 后返回已经完整评估的最佳根。

## 根动作集合

候选不再来自角色方向与武器落点的笛卡尔积，而是：

1. 当前 Phase 2.5 基线；
2. SURVIVE 火控；
3. SCORE 火控；
4. Full 下的 DESPERATION 火控；
5. 火箭可用时的暂缓火箭方案；
6. 全部暂缓开火方案。

候选按实际动作稳定去重。控制器分配由 Engine 缓存结果传入，不在搜索中
重新分配。默认关闭的 Bomb / Stun（规格中的 Dizzy 主动能力）不会生成根。
模拟器不支持的物品动作会拒绝进入 Phase 3，并安全复用 Phase 2.5 基线。

## 场景与证书

- Lite 固定保留 `MAXIMUM_STATION_PROGRESS` 保守场景。
- Full 保留该保守场景，再加入其余场景中后验权重最高者。
- 抽样后的场景权重重新精确归一化。
- TailEstimator 尚未实现时，基地在短 horizon 内存活但尚未到天亮的证书
  标记为 `UNKNOWN` 且 `secured=False`，避免把局部存活冒充整夜安全。
- 已经出现基地死亡的结果仍保留 `MARGINAL/UNSAFE` 分类。

## 性能改造

- 机器人移动由每个候选格重复 BFS 改为共享反向距离图。
- 距离图缓存键只包含真实地图拓扑，不包含不影响路径的回合号。
- Phase 2.5 状态级联合火控使用有界缓存，并忽略不影响目标/伤害的回合元数据。
- 所有缓存均有容量上限；输入状态为不可变 dataclass。

确定性 `phase3_night_request.json`，50 个连续夜间回合，控制器分配和 Phase 2.5
基线在计时外准备，Lite/Full 分别在独立 Python 进程执行：

| 档位 | 首次冷调用 | P50 | P95 | P99 | 目标 |
|---|---:|---:|---:|---:|---:|
| Lite | 11.6743ms | 1.8086ms | 1.9492ms | 1.9585ms | P95 <5ms |
| Full | 18.0296ms | 4.0135ms | 4.3665ms | 6.0622ms | P95 <12ms |

首次整回合夜间决策仍包含控制器冷分配，定向测试观测约 20～31ms；重复请求
由会话缓存直接返回。该数字与上述 Phase 3 搜索本体分开记录。

## 外部验收

真实对局 JSON 为私有文件，本阶段不要求上传，也不构造伪造“真实日志”。
Lite 10%～25%、Full 不超过 5% 的调用比例需要在用户侧真实回放中通过聚合遥测
验收；只需返回调用率、P95/P99、基地承伤和异常计数，无需提供原始 JSON。
